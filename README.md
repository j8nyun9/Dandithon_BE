# 단디보상운동 API — 로컬 개발용

제공받은 BE 저장소의 Node.js 구조와 `/api`·`{data}` 응답 약속을 기반으로 만든 로컬 시제품입니다. Node 22.19에서 테스트했습니다. SQLite 내장 모듈은 실험적 기능이며, 이 버전은 실사용·인터넷 공개·Vercel 배포용이 아닙니다. 학생 계정과 미션은 시연용이며 대학 이름은 참여 학교를 사용합니다. 로그인·미션·참여 확인·리그 화면은 시연 API에 연결되어 있으며 나머지 일부 화면은 mock 데이터를 사용합니다.

현재 구현 범위와 다음 순서는 [개발 현황](docs/implementation-status.md)을 참고하세요.

## 실행

```powershell
npm.cmd run seed
npm.cmd run dev
```

`http://127.0.0.1:3001/api/health`에서 확인합니다. 시연 데이터 파일은 `dandi.sqlite`입니다. `seed`는 기존 사용자가 있으면 초기화하지 않습니다. `.env.example`은 참고용이며 자동으로 로드하지 않습니다. 필요한 환경변수는 실행 전 PowerShell에서 설정합니다. 테스트: `npm.cmd run check`, `npm.cmd test`.

데모 암호와 기본 비밀키는 운영용이 아닙니다. 공고·사용자·학교 검증, TLS, 비밀번호 방어, 로그인 제한, CORS, 데이터 보존·삭제 및 법적 근거 등은 아직 필요합니다. 실제 개인정보와 증빙 파일을 넣지 마세요.

## AI 설정

기본 `AI_MODE=mock`. 실제 OpenAI 요청을 시도하려면 서버 실행 전에 `$env:AI_MODE='live'`와 `$env:OPENAI_API_KEY='키'`를 설정하세요. 키는 채팅·코드·저장소에 공유하지 않습니다. 서버 환경에서 키를 읽으며, 실제 호출 실패나 키 미설정 시 응답의 `mode`가 `mock`으로 명시됩니다. 실제 API 및 품질은 아직 검증되지 않았습니다. 공고는 외부 모델에 전달되므로 제공·이용 권한을 확인하세요. 모델은 공고 구조화와 추천만 제안합니다. 공식 실적은 반드시 담당자가 확인·승인합니다.

## FE 연동 및 API

상세 요청과 응답은 [docs/api.md](docs/api.md) 참고. FE의 Vite 프록시가 `/api`를 `127.0.0.1:3001`로 전달합니다. 기존 `GET /api/activities`는 `id`, `title`, `minutes`, `points` 필드와 공개 접근을 유지하되 임시 0 값을 반환합니다. 랭킹 점수나 활동 시간을 의미하지 않습니다. 새 화면은 `/api/missions` 등 새 API를 사용하고 로그인 토큰을 `Authorization: Bearer <token>`으로 보내야 합니다. 로그인·미션·확인 요청·관리자 승인·리그 화면이 로컬 API에 연결되어 있습니다.

리그 산식은 승인된 실적별 인정 기여량을 분야 가중치로 배분해 합산하는 **시연용 임시 산식**으로 확정된 50/30/20 산식이 아닙니다. 혈액 관련 데이터는 실서비스 점수에서 제외하고 시연 자료에만 축 값을 표시합니다. 기관 통계의 5명 미만 감추기는 완전한 익명화를 보장하지 않으며, 클릭은 신청·참여·완료가 아닙니다. 동일 외부 ID와 동일 참가자·미션은 중복 차단하지만 다른 ID로 유입된 동일 활동은 사람이 대조해야 합니다.

## 배포 및 제출 전 남은 작업

- PostgreSQL/Supabase 마이그레이션과 인증·RLS, 사용자/대학/학기 관리와 소속 확인, Vercel 호환 서버 및 운영 보안 구현. `db/schema.sql`은 SQLite 초기 스키마입니다.
- 공고 이용권, 정확한 모집 기간 및 자격 검증, FE 화면 실제 연결, AI 실 호출과 품질 평가, 개인정보 보호와 통계 차분 공격 대응을 검증합니다.
- 점수의 정식 산식·기관 확인 범위·헌혈 표시 정책·실적 중복 대조 절차를 확정합니다.
- 공개 GitHub, 실제 서비스 주소, 최종 발표 PDF(20장·100MB 이하), 별도 심사용 계정과 시연 흐름을 제출 전에 확인합니다. 원격 변경은 사용자의 별도 지시를 따릅니다.
- 공지의 ‘11월 10일(토)’은 불일치합니다. **2026년 11월 10일은 화요일**이므로 실제 마감 날짜와 시각을 운영진에 확인합니다. 마감 뒤 소스·서비스·제출 자료 변경 금지에 유의합니다.

## 로컬 화면 연동 시연

FE와 BE 서버를 각각 켠 다음 FE의 로그인 화면에서 시연 계정을 사용합니다. 학생 `knu@demo.local` / `DemoStudent!123`으로 활동하기 → 참여 인증 → 확인 요청을 보냅니다. 로그아웃 후 관리자 `admin@demo.local` / `DemoAdmin!123`으로 로그인해 운영자 화면에서 실제 완료 여부를 별도로 확인한 뒤 승인합니다. 학생으로 다시 로그인해 대학 리그를 확인합니다. 백엔드 코드를 변경한 경우 서버를 재시작하세요.

학생의 확인 요청은 증빙 업로드가 아니며, 실제 완료 여부는 기관이 별도로 확인해야 합니다. 1365·VMS 공고 검색은 원문을 직접 확인하는 실험 기능이며 공식 실적 연동을 제공하지 않습니다. 시상·의연록은 준비 중이며 홈·기관 화면은 서버 값을 사용합니다. 활동하기와 대학 리그도 가상 시연 DB를 사용합니다. 데이터 초기화는 서버를 끈 뒤 로컬 `dandi.sqlite`를 별도로 백업/삭제하고 `npm.cmd run seed`로 다시 준비합니다.


관리자만 미션을 등록할 수 있습니다. 예전 버전에서 등록자를 기록하지 않은 미션은 관리자 화면에서 원문을 확인하기 전까지 학생에게 노출하지 않습니다. 모집 기간이 지난 미션은 확인 후에도 노출되지 않습니다.


모집 기간은 시작일·마감일에서 자동 표시합니다. 모집 안내는 선택 사항입니다. 신규 미션의 인정 기여량(0.01~10, 소수 둘째 자리)은 공식 봉사시간이 아닌 리그용 시연 수치이며 등록 후 변경할 수 없습니다. 기존 미션은 기여량 1로 유지됩니다. 승인할 때 확인 출처·외부 실적 ID는 필수가 아니므로 서로 다른 미션 또는 서로 다른 외부 기록으로 들어온 동일 실적은 담당자가 수동으로 대조해야 합니다.


### 봉사활동 자동 수집 (실공고 연결 검증 전)
관리자 화면에서 개별 URL을 입력하지 않습니다. 서버가 켜져 있을 때 24시간 간격으로 1365 공식 지역별 목록과 OpenAI를 통한 VMS 검색을 확인합니다. 1365는 대구·경북의 모집 중인 성인 대상 목록 각 첫 페이지에서 후보를 찾고, 공식 상세 공고를 다시 읽어 모집 상태와 기간을 확인합니다. 모집 기간이 없고 공식 모집중 표시가 있는 경우에는 기간 미정으로 표시합니다. AI 분류에 실패하거나 공식 원문을 읽지 못하면 등록하지 않으며, 재확인이 오래된 공고는 학생 목록에서 숨깁니다. 검색과 분류에는 OpenAI API 사용 요금이 발생할 수 있습니다. 서버에서 VMS로 연결할 수 없다면 VMS 공고는 수집되지 않습니다.

VMS 직접 연결이 어려운 경우 `scripts/wrangler-vms.jsonc`의 Cloudflare Worker를 배포하고 서버에 `VMS_RELAY_URL`과 `VMS_RELAY_TOKEN`을 설정합니다. Worker의 Secret `PROBE_TOKEN`은 서버의 `VMS_RELAY_TOKEN`과 같아야 합니다. Worker는 VMS 상세 공고의 공개 항목만 추출하며 신청자 목록을 반환하지 않습니다. 중계 서버가 원문에 연결하지 못하거나 읽은 공고의 모집 상태를 확인할 수 없으면 자동 등록이 보장되지 않습니다. Cloudflare 실행 위치와 VMS 접근 가능 여부는 환경에 따라 달라질 수 있습니다.

PowerShell에서 서버 실행 전 `$env:AI_MODE='live'`와 `$env:OPENAI_API_KEY='발급받은 키'`를 설정하세요. `OPENAI_MODEL`은 분류·추천 모델, `OPENAI_SEARCH_MODEL`은 도메인 제한을 지원하는 검색 모델을 지정합니다. 검색 모델 기본값은 `gpt-6-luna`입니다. 학생 추천에도 같은 OpenAI 키를 사용합니다. 키를 코드나 Git에 올리지 마세요. 서버가 꺼져 있으면 정기 수집이 실행되지 않습니다. 실제 사이트의 접근 정책, 검색 결과 및 HTML 구조와의 호환성은 키와 네트워크가 준비된 뒤 확인해야 하며, 현재는 활동이 수집되지 않을 수 있습니다. 공식 신청과 실적 승인은 각각 해당 사이트와 관리자가 처리합니다.

학교 규모에 대한 AI 검색 및 자동 갱신은 사용하지 않습니다. 현재 활성 학기에는 시연용 대략적인 재학생 수를 사용하며 화면에 추정치로 표시합니다. 실제 공식 수치를 입력한 기록은 덮어쓰지 않습니다. 출처 조사와 시연값은 `docs/school-population-sources.md`에 기록합니다.

자동 수집은 한 번에 확인된 공식 개별 공고 최대 40개를 후보로 처리합니다. 관리자는 최근 후보와 등록 보류 사유를 확인하고, 진행 중인 검색이 없으면 24시간 제한 없이 수동 검색할 수 있습니다. 수동 검색은 자동 검색 일정을 변경하지 않습니다. 검색은 API 요금을 발생시킬 수 있습니다. 1365 공고의 지역은 공식 지역 검색 결과로 확인하고, 제목·기관·기간과 모집 상태는 상세 원문에서 다시 확인합니다. 첫 페이지만 검색하므로 전체 공고를 보장하지 않습니다.

Render에서 공식 사이트에 연결되지 않을 때, 한국에서 해당 사이트에 접근 가능한 PC에서 관리자 수집기를 한 번 실행할 수 있습니다. 사전에 `.env.local`에 `DATABASE_URL`, `OPENAI_API_KEY`, `.deployment-credentials`에 관리자 자격 정보가 있어야 하며 이 파일들을 Git이나 채팅에 올리지 않습니다. 서버에 해당 버전이 배포된 후 백엔드 폴더에서 `node --env-file=.env.local --env-file=.deployment-credentials scripts/collect-local.js`를 실행합니다. `--check`를 덧붙이면 실제 수집 없이 서버 지원 여부만 확인합니다. PC 실행은 일회성이며 컴퓨터가 꺼져 있을 때 동작하지 않습니다. 동일 DB의 서버 수집과 PC 수집은 잠금으로 중복 실행을 방지합니다. PC 수집 중 사용되는 OpenAI API 요금은 별도입니다.
